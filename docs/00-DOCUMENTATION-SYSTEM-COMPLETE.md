## 📏 文档编写规范

### 每份文档必须有的头部

```markdown
# [文档标题]

**文档类型**: [analysis|guide|reference|template|process]  
**版本**: 1.0  
**最后更新**: 2026-02-28  
**维护者**: [name]  
**代码对应版本**: v2.0.0 [仅参考文档]  
**下次审查**: 2026-03-31  

## 概述
[简要说明]

## [内容...]

## 相关文档
- [文档名](path/to/doc.md)

## 变更历史
- v1.0 (2026-02-28): 初始版本
```

### 文件命名规则

✅ **允许**:
```
my-document.md          - 英文、连字符
01-quick-start.md       - 数字前缀排序
```

❌ **禁止**:
```
my_document.md          - 下划线
快速开始.md             - 中文名
MyDocument.md           - 大小写混合
```

### 链接规范

✅ **推荐 (相对路径)**:
```markdown
[文档](./01-quick-start.md)
[参考](../3-references/api/public-api.md)
```

❌ **禁止 (绝对路径)**:
```markdown
[文档](/media/stone/data/dev/docs/...)
```

## 🔄 文档与代码对齐流程

### 代码变更时

```
代码变更 (Commit)
    ↓
检查是否涉及公开 API
    ↓ 是 → 更新 3-references/api/*.md
检查是否改变使用方式
    ↓ 是 → 更新 2-guides/*.md
检查是否影响配置
    ↓ 是 → 更新 3-references/config/*.md
    ↓
在同一 PR 中提交代码和文档
```

### 代码审查时检查

- [ ] 代码变更是否有对应文档更新？
- [ ] 示例代码是否与新代码一致？
- [ ] 是否有过时文档需要更新？
- [ ] 新增 API 是否有对应文档？
